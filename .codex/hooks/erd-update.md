# ERD 갱신

Codex의 `Stop` 훅이 엔티티·내장 값 객체·매핑 상위 클래스의 영속 구조를 이전 확인 기준과 비교한다. 필드·관계·매핑 변경이 있으면 ERD 확인을 위해 한 번 더 작업을 이어가게 한다. 메서드 본문·주석·일반적인 포맷 변경은 제외한다.

## 갱신 규칙

- 실제 코드의 엔티티와 관계만 그린다. 외래키와 단순 ID 참조, 필수·선택 관계와 다중성을 구분한다. 내장 값 객체를 테이블로 추가하지 않는다.
- `diagram-design` 스킬로 `docs/erd/overview.html`과 `detailed.html`을 수정하고 SVG를 내보낸다. 이 프로젝트의 아래 표현 규칙을 스킬의 기본 스타일보다 우선한다.
- 관계는 까마귀발(Crow’s Foot) 기호로 표시한다. 선 중간 설명, 하단 범례, 보이는 제목은 넣지 않는다. 접근성용 SVG `title`·`desc`는 유지한다.
- 배경과 테이블 내부는 `#FFFFFF`로 통일한다. 바깥 여백은 사방 24px로 맞추고, 불필요한 공간을 줄인다. 원래 캔버스 크기를 유지하려고 빈 공간을 추가하지 않는다.
- 요약본은 관계와 식별 필드만, 상세본은 전체 영속 필드·타입·제약을 보여준다. SVG에 실제 폭·높이를 지정하고 글자·기호의 겹침과 잘림을 확인한다.
- README의 ERD는 패키지 구조 다음에 둔다. 상세 링크는 [Wiki ERD](https://github.com/f-lab-edu/car-wash-life/wiki/ERD)를 가리킨다.
- `docs/erd/detailed.md`에는 테이블별 역할과 관계를 갖는 이유를 1~2문장으로 적는다. 엔티티 코드 링크는 유지하고, 긴 필드 표와 중복 설명은 넣지 않는다.

## 완료 확인

1. 실제 코드와 두 ERD의 엔티티·필드·관계를 대조하고 스킬의 자체 검사와 화면 검증을 수행한다.
2. 원고와 링크를 확인한 뒤 `python3 .codex/hooks/erd_sync.py --record`로 `docs/erd/model-state.json`을 갱신한다. 그림 변경이 필요 없다고 판단했다면 이유를 보고하고 기준만 갱신할 수 있다.
3. Wiki 게시와 푸시는 사용자가 요청했을 때만 수행한다. 게시할 때는 본문뿐 아니라 최신 SVG와 HTML 원본도 함께 반영한다. 이미지 파일명에 내용 해시를 넣어 이전 이미지 캐시를 피하고, 게시 화면에서 새 그림이 표시되는지 확인한다.

## 훅 실행

`.codex/hooks.json`의 프로젝트 훅을 사용한다. Codex에서 훅을 검토하고 신뢰해야 자동 실행된다. CLI에서는 `/hooks`로 검토할 수 있다.

수동 검증: `printf '%s' '{"hook_event_name":"Stop","stop_hook_active":false}' | python3 .codex/hooks/erd_sync.py`

기준과 같으면 `{}`, 다르면 한 차례 작업 재개 요청을 반환한다. 검사 실패는 경고로 보고하고 작업을 반복해서 막지 않는다. 훅은 그림 생성·파일 수정·Wiki 게시·푸시를 직접 실행하지 않는다.
