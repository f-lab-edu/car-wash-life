## 코드 스타일

- Java 소스와 테스트 코드의 포맷 기준은 프로젝트 루트의 `GoogleStyle.xml`이다. 생성·수정 전에 파일을 읽고 반드시 따른다.
- Java 전용 설정과 상위 공통 설정을 함께 확인한다. 커스텀 설정을 표준 Google 스타일이나 다른 포맷터의 기본값으로 대체하지 않는다.
- DI용 생성자는 Lombok `@RequiredArgsConstructor`로 생성하고, 주입할 의존성은 `private final` 필드로 선언한다. 필드 대입만 하는 생성자를 직접 작성하거나 `@AllArgsConstructor`로 대체하지 않는다.
- 도메인 검증·초기화나 설정 값 변환처럼 생성자 본문이 필요한 경우에는 명시적 생성자를 유지한다.
- 생성자·메서드의 매개변수를 여러 줄로 선언할 때 첫 매개변수는 여는 괄호와 같은 줄에 둔다. 이후 매개변수는 첫 매개변수의 시작 열에 맞추고, 닫는 괄호와 여는 중괄호는 마지막 매개변수와 같은 줄에 둔다.
- 메서드·생성자 호출은 `GoogleStyle.xml`의 줄 길이 제한 안에 들어가면 한 줄로 작성한다. 여러 줄이 필요할 때도 첫 인자는 여는 괄호와 같은 줄에 둔다.
- 완료 전에 변경한 Java 파일의 들여쓰기, 줄바꿈, 정렬 및 import 구성을 이 기준으로 검토한다. 자동 포맷·검증 도구를 사용한 경우 해당 XML 적용 여부를 확인하고, 실행하지 못한 자동 검증은 명시한다.

### 세로 배치

- 관련성이 높은 코드는 가까이 배치하고, 서로 다른 처리 단계·개념은 빈 줄 하나로 구분한다. 같은 처리에 속하는 선언·검증·사용 사이에는 불필요한 빈 줄을 넣지 않는다.
- 상위 흐름을 먼저, 세부 구현을 그 아래에 둔다. 보조 메서드는 호출자 아래 가까이 배치하고, 여러 메서드가 공유하면 관련 호출자 묶음 바로 아래에 둔다. 접근 제한자만으로 메서드를 일괄 분류하지 않는다.
- 지역 변수는 첫 사용 가까이에 선언하고, 클래스 필드는 상단에 모은다. 배치를 바꾸기 위해 부수 효과가 있는 연산이나 잠금·저장 순서를 변경하지 않는다.
- 주석·어노테이션·대상 선언은 빈 줄 없이 붙인다. 메서드 사이는 빈 줄 하나로 구분하며, 세로 배치를 맞추려고 불필요한 메서드를 추출하거나 파일을 분리하지 않는다.

참고: [Clean Code 5장 Formatting](https://www.oreilly.com/library/view/clean-code-a/9780136083238/chapter05.xhtml)의 Vertical Formatting. 구체적인 포맷 값은 `GoogleStyle.xml`을 따른다.
