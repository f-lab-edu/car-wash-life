## 지침 1차 개선

- 일반적인 SOLID 나열을 데이터 소유자·함께 바뀌는 지점·추상화 비용의 판단으로 교체했다.
- 목적이 다른 API 입력 검증과 도메인 불변조건 검증을 구분했다.
- 저장 전 검증은 입력·객체 생성에 한정했다. 동시성 잠금과 저장된 후보의 대표 선택까지 앞당기지 않는다.
- 예외 범위 축소와 타입 구분의 선택 기준, 서비스와 DTO의 변환 책임을 명시했다.
- 에이전트는 요청한 비교 범위와 관련 호출부를 확인하고, 테스트 통과와 설계 적절성을 별도로 판단하게 했다.
- 공통 AGENTS.md는 늘리지 않았다. 세 역할 지침은 각 역할의 판단만 다룬다.

## PR #14 적용과 피드백

검토 범위는 마지막 병합 커밋만이 아닌 `feat/7-member-car-wash-registration...feat/8-member-car-wash-query` 전체와 호출부다.

- **수정:** 조회 서비스의 긴 상세 응답 매핑을 `CarWashDetailDto.Response.from`으로 이동했다. 평탄한 JSON과 필드 값은 유지한다.
- **이미 충족:** 이력의 신뢰도 계산, 생성 메서드, Coordinates·시설 enum의 검증, 생성 enum과 과거 저장 이름 읽기, 검증 후 저장, 좁은 예외 변환과 cause 보존.
- **유지 근거:** 대표 선택 Policy는 여러 이력의 비교 규칙을 소유한다. 조회의 쓰기 트랜잭션·잠금은 대표 반영에 필요하다.
- **제외:** 공통 인증 서비스, 별도 Mapper 계층, 새 이름 값 객체는 이번 리뷰에서 필요성이 확인되지 않았다.
- **검증:** 전체 테스트 187개 성공. 상세 응답의 전체 값·시간·회원 ID 비노출, 동점 선택, 90일 재평가, 갱신 시각과 동시 수정 테스트를 유지했다.
- **지침 평가:** 원문과 갱신 지침만 받은 독립 분석도 같은 매핑 문제를 찾고 대표 Policy 유지 근거를 설명했다. PR #14에서 새 지침 결함은 확인되지 않았다.

로컬 DB 검증은 H2 PostgreSQL 모드이며 실제 PostgreSQL의 모든 동작을 검증한 것은 아니다.

## PR #15 적용과 피드백

PR #14의 검증된 결과를 먼저 병합하고 전체 테스트 228개 성공을 확인한 다음 사진 기능을 검토했다.

- **수정:** 사진 근거를 내부에 가진 이력이 신뢰도를 직접 계산하게 했다. 호출부의 `calculateConfidence(history.hasEvidencePhotos(), evaluatedAt)`를 `calculateConfidence(evaluatedAt)`로 바꿨다. 외부에서 사진 가점을 임의로 주거나 빼는 인자를 제거했다.
- **수정:** `ValidatedPhoto`와 `PhotoContent`가 생성·반환 배열을 복사하게 했다. 검증 후 바이트, 값의 동등성·해시가 외부 변경으로 바뀌지 않는다. 업로드는 accessor 결과를 한 번 받아 저장과 크기 확인에 재사용한다.
- **지침 보완:** 기존 불변 값 원칙을 구현에서 놓쳤으므로 record·배열·컬렉션과 alias 변경 테스트를 명시했다. 긴 배열 코드는 조건부 참고 파일로 분리하고, AGENTS.md에 이미 있는 패키지 경로 반복을 설계 지침에서 제거했다.
- **유지 근거:** 이미지 Validator와 Storage는 입력/I/O 경계의 실제 역할을 갖는다. 파일 쓰기가 생성한 키로 메타데이터를 만들며, 먼저 입력을 검증하고 DB 실패에는 파일 보상 처리를 유지한다.
- **유지 근거:** 잠금 전 사진 ID 거절과 이력 자체의 검증, 잠금 후 소유권 확인과 직접 도메인 호출의 불변조건은 목적이 다르다. 검증을 삭제하거나 공유 타입을 추가할 근거는 부족했다.
- **보존한 계약:** 신규 사진은 요청당 최대 5개, 누적 사진과 최초 출처는 유지, 가점은 새 관찰 근거만 사용, 사진 한 번 연결, 제출 실패 시 선업로드 사진 재사용, 파일 읽기/쓰기 실패의 원인과 공개 오류 분리.
- **재현과 검증:** 추가한 배열 불변성 테스트 두 개는 수정 전 실패했고 수정 후 성공했다. 전체 테스트 230개 성공, 독립 검토에서 필수 수정 사항 없음.

## 지침의 컨텍스트 비용과 한계

- 공통 AGENTS.md는 29행 그대로다. apply-review는 30행, 역할 지침은 각각 11~12행으로 유지했다.
- 사례 분석은 이 문서, 배열의 실제 코드는 조건부 `domain-examples.md`에 두었다. 일반 작업에서 리뷰 이력을 모두 읽을 필요가 없다.
- 사전 정답 없이 지침과 수정 전 코드만 받은 별도 에이전트가 배열 불변성·사진 근거 재전달을 찾고 대표 선택 Policy 유지 근거도 설명했다.
- 이 평가에서 application 전체에 Spring·DB 테스트를 요구할 수 있는 모호함이 드러났다. 순수 계산·값 검증은 패키지와 관계없이 단위 테스트하고, 하위 계층을 조합하는 서비스는 통합 테스트하도록 기존 문장을 교체했다.
- YAML frontmatter와 에이전트 TOML 구문을 검증했다. 문법 검증과 실제 판단 능력 검증은 구분한다.
- Java 포맷은 GoogleStyle.xml을 기준으로 직접 확인했다. 해당 XML을 적용한 자동 포맷 검증기는 실행하지 않았다.
