# 세차장 탐색·제보·상세 조회

적용 API는 탐색 `GET /car-washes`, 이름 검색 `GET /car-washes/search`, 등록 `POST /car-washes`, 수정 `POST /car-washes/{carWashId}/histories`, 상세 조회 `GET /car-washes/{carWashId}`다.

탐색과 이름 검색, 상세 정보는 로그인 여부와 회원 상태에 관계없이 조회할 수 있다. 등록과 수정에는 활성 회원의 AccessToken이 필요하다.

## 세차장명 검색

`GET /car-washes/search?keyword=세차생활`로 현재 대표 이름에 검색어가 포함된 세차장을 검색한다.
`keyword`의 앞뒤 공백은 제거하고 내부 공백은 보존한다. 정리한 검색어는 1~100자여야 하며, 누락하거나 공백뿐이거나 100자를 초과하면 `400 VALIDATION_ERROR`를 반환한다.
부분 검색은 대소문자를 구분하며 `%`, `_`, 작은따옴표 등도 이름에 포함된 일반 문자로 처리한다. 주소와 비대표 이력의 이름은 검색하지 않는다.

응답은 지도 탐색과 같은 `carWashes`, `hasMore` 구조다. ID 오름차순으로 최대 100개를 반환하고, 101번째 결과가 있으면 `hasMore`가 `true`다.
각 항목에는 대표 이름, 주소, 좌표와 전체 제보 건수, 최근 제출 시각, 최초 등록 시각을 제공한다. 결과가 없으면 `carWashes`는 빈 목록이고 `hasMore`는 `false`다.

이번 변경은 이름 검색의 첫 구현이다. 현재 위치에 따른 거리 표시와 정렬, 페이지 조회, 지역 검색은 아직 제공하지 않는다. `distanceMeters`는 `null`이며, 추가 결과를 찾으려면 더 구체적인 이름으로 검색한다.

## 지도 범위 탐색

`GET /car-washes`에 지도의 남서쪽·북동쪽 좌표를 전달한다. 현재 위치는 필요하지 않다.

| 필수 쿼리 파라미터 | 허용 범위 |
|---|---|
| southwestLatitude | -90 ~ 90 |
| southwestLongitude | -180 ~ 180 |
| northeastLatitude | -90 ~ 90 |
| northeastLongitude | -180 ~ 180 |

현재 위치를 함께 보내려면 `currentLatitude`와 `currentLongitude`를 모두 전달한다. 위도·경도 허용 범위는 위와 같으며, 하나만 보내거나 잘못된 좌표를 보내면 `400 VALIDATION_ERROR`를 반환한다.
현재 위치는 지도 범위 밖이어도 된다.

남서쪽 위도·경도는 각각 북동쪽 값 이하여야 한다. 네 경계를 포함하며, 두 좌표가 같은 범위도 허용한다.
누락·숫자가 아닌 값·NaN·무한대·허용 범위를 벗어난 좌표·역전된 범위는 `400 VALIDATION_ERROR`를 반환한다. 날짜변경선을 가로지르는 범위는 지원하지 않는다.

```http
GET /car-washes?southwestLatitude=37.4&southwestLongitude=126.9&northeastLatitude=37.6&northeastLongitude=127.1
```

```json
{
  "carWashes": [
    {
      "carWashId": 1,
      "name": "세차생활",
      "address": "서울시",
      "latitude": 37.5,
      "longitude": 127.0,
      "reportCount": 3,
      "latestSubmittedAt": "2026-10-09T12:00:00+09:00",
      "createdAt": "2026-10-07T12:00:00+09:00",
      "distanceMeters": null
    }
  ],
  "hasMore": false
}
```

현재 대표 좌표로 검색하고 대표 이름·주소·좌표를 반환한다. 주소가 미확인이면 `null`이다. 과거 제보의 좌표는 검색에 사용하지 않는다.
현재 위치가 없으면 세차장 ID 오름차순으로, 있으면 거리 오름차순·같은 거리에서는 ID 오름차순으로 최대 100개를 반환한다. 더 있으면 `hasMore`가 `true`다. 범위 안 세차장의 전체 건수는 세지 않는다. 결과가 없으면 `carWashes`는 빈 목록이고 `hasMore`는 `false`다.
추가 결과 여부는 상한보다 한 건 더 조회해 확인하며, 확인용 항목은 응답에 포함하지 않는다.
추가 결과를 탐색하려면 지도 범위를 좁혀 다시 요청한다. 다음 페이지 조회는 제공하지 않는다.

| 제보 활동 정보 | 의미 |
|---|---|
| reportCount | 최초 등록과 모든 수정 제보를 합한 건수 |
| latestSubmittedAt | 대표 여부와 관계없이 가장 최근에 제출된 제보의 시각 |
| createdAt | 세차장이 서비스에 최초 등록된 시각 |

최근 제보 시각은 관찰 시각(`observedAt`)이나 대표 정보 갱신 시각(`updatedAt`)과 다르다. 대표로 선택되지 않은 제보도 건수와 최근 제출 시각에 반영한다.

`distanceMeters`는 현재 위치에서 대표 좌표까지의 구면 최단거리이며 단위는 미터다. 도로 이동 거리가 아니며, 반지름 6,371,008.8m인 구형 지구 모델의 Haversine 수식으로 계산한다.
거리 계산값을 반올림하지 않고 정렬·반환하며, 표시 자릿수는 클라이언트에서 정한다. 현재 위치가 없으면 `null`이다. 거리순 정렬과 조회 상한은 DB에서 적용한다.

```http
GET /car-washes?southwestLatitude=37.4&southwestLongitude=126.9&northeastLatitude=37.6&northeastLongitude=127.1&currentLatitude=37.5&currentLongitude=127.0
```

## 확인한 정보와 미확인 정보

사용자는 관찰 시점에 직접 확인한 값을 제출한다. 이름·위도·경도는 필수이며, 가격·주소·시설 등 선택 항목을 모르면 비워서 제출할 수 있다.
이전 제보의 값을 다시 제출하려면 해당 관찰 시점에 확인한 값이어야 한다.

등록과 수정은 제출 후 상태 전체를 나타내는 스냅샷을 받는다. 수정 요청에서 선택 항목을 생략하거나 null로 보내면 기존 값을 유지하지 않는다.
주소·가격·베이 수는 null로, 시설 상태는 UNKNOWN으로 기록한다. 0원은 확인한 무료 가격이며 미확인과 다르다.
이전 값은 과거 이력에 남는다.
사진은 별도로 `photoIds`에 이번 요청의 신규 사진 ID만 제출하며, 수정 시 생략/null/빈 목록이면 기준 이력의 사진을 유지한다.

예를 들어 기준 이력의 가격이 3,000원이어도, 이름과 좌표만 확인하고 가격은 모른다면 다음처럼 수정 요청을 보낸다.
아래 값과 시점은 요청 형식을 설명하기 위한 예시다.

```json
{
  "baseHistoryId": 123,
  "visitExperience": "USED",
  "observedAt": "2026-10-07T12:00:00+09:00",
  "information": {
    "name": "새 세차생활",
    "latitude": 37.5,
    "longitude": 127.0
  }
}
```

새 수정 이력의 가격은 3,000원이 아닌 미확인(null)으로 기록된다. 전체 값이 기준 이력과 같으면 변경 없는 수정으로 거절한다.
서버는 사용자의 실제 현장 확인 여부까지 검증하지 않으므로, 클라이언트는 과거 값을 확인 없이 새 제보에 자동으로 포함하지 않아야 한다.

## 관찰 시점과 신뢰도

| 항목 | 의미 |
|---|---|
| observedAt | 사용자가 이번 제보에 입력한 정보를 확인했다고 제보한 시점 |
| submittedAt | 서버가 제보를 받은 시점 |
| confidence | 해당 제보의 이용 경험·관찰 최근성·사진 근거로 계산한 대표 선택용 점수 |

신뢰도는 모든 항목이 입력되었거나 사실임을 보증하는 값이 아니며, 개별 항목의 정확성을 나타내는 확률도 아니다.
관찰 시점이 최근이어도 비워서 제출한 가격은 미확인이다.
등록·수정 응답의 점수는 제출 시점에, 상세 조회 응답의 점수는 조회 시점에 평가하므로 같은 이력도 시간 경과에 따라 점수가 달라질 수 있다.

상세 조회는 원장에 저장된 대표 제보의 전체 스냅샷과 관찰 시점·신뢰도를 함께 반환한다. 대표 제보는 가장 최근에 제출한 제보와 다를 수 있다.
미확인 항목을 다른 이력의 값으로 채워 반환하지 않는다.

## 대표 정보의 갱신과 조회

최초 등록은 생성한 이력을 바로 대표로 반영한다. 수정은 같은 세차장의 원장 행에 쓰기 잠금을 잡고 이력 저장과 대표 선정을 한 트랜잭션에서 처리한다.
상세 조회는 쓰기 잠금 없이 저장된 대표 이력을 읽으며 전체 이력을 비교하거나 원장을 갱신하지 않는다.
수정이 진행 중이면 이전에 커밋된 대표를 반환할 수 있고, 커밋 후 시작한 조회에는 새 대표가 반영된다.

조회 시점에는 저장된 대표 이력 하나의 신뢰도만 계산한다. 시간 경과에 따른 대표 재선정이나 원장 보정은 조회에서 수행하지 않으며, 다음 수정 시 전체 이력을 다시 평가한다.

## 변경 항목과 출처

changedFields는 기준 이력과 값이 달라진 항목이다. 이전과 같은 가격을 다시 확인해 제출해도 가격은 변경 항목에 포함되지 않는다.
도메인의 getSourceHistory()는 그 값이 변경된 이력을 따라가는 기능이며, 마지막 재확인 시점을 뜻하지 않는다.
이번 API는 항목별 재확인 이력을 별도로 제공하지 않는다.

## 이력 조회 인덱스

수정 시 대표 선정을 위해 실행하는 `findAllByCarWashId`는 `car_wash_history.car_wash_id`의 비고유 인덱스를 사용하도록 정의한다.
다른 세차장의 이력까지 순차 탐색하는 비용을 줄이며, 해당 세차장의 모든 이력을 읽고 평가하는 비용은 남는다.
실제 인덱스 사용 여부는 데이터 분포와 PostgreSQL 실행 계획에 따라 달라질 수 있다.

JPA의 `@Index`는 스키마 생성에 반영되며, 현재 `ddl-auto=update` 설정에서는 기존 DB도 앱 재시작 시 일반 인덱스 생성을 시도한다.
쓰기 요청을 막지 않는 동시 생성 방식을 적용하려면 앱 재시작 전에 다음 SQL을 트랜잭션 밖에서 실행한다.

```sql
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_car_wash_history_car_wash_id
    ON public.car_wash_history (car_wash_id);

ANALYZE public.car_wash_history;
```

`IF NOT EXISTS`는 이름만 확인하므로, 적용 후 `pg_indexes`의 인덱스 정의와 `pg_index.indisvalid`가 true인지 확인한다.
이미 같은 이름의 인덱스가 있어도 정의가 다르거나 유효하지 않으면 별도로 확인해야 한다. 실행 계획도 함께 확인한다.
